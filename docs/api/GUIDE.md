# Lazy Sleeper API — client guide

Hand-written companion to the generated `README.md` / `openapi.json` (regenerated by
`lazy api export`; this file is not). The reference tells you *what* each endpoint takes and
returns where the app types it; this guide covers the rest: the client workflows, the response
shapes of the endpoints that return untyped JSON, and what the fields actually mean.

## Getting connected

- **`lazy serve`** starts the API (embedded uvicorn) and prints the primary LAN URL plus a URL
  per page. Default port 8000. No auth — the host is reached over the LAN or Tailscale only.
- Interactive docs at `/docs`, machine spec at `/openapi.json`, liveness at `/health`
  (`{"status": "ok"}`).
- All timestamps are ISO-8601 UTC. All JSON field names are `snake_case`.

## Workflow 1 — draft night (the main client loop)

1. **Before the draft room opens:** `POST /draft/{draft_id}/start` with
   `{"season": 2026}`. This does the heavy pre-draft load (board + ADP + player lookup —
   a few seconds) and starts polling Sleeper on a background thread. Idempotent while the
   runner is alive; `already_running: true` in the response tells you it was. `my_slot` may be
   `null` early — Sleeper often fills `draft_order` late; the runner picks it up mid-draft.
   **Timeouts to expect:** a healthy `start` answers in a few seconds (the board build). Give
   it a client timeout of ~60 s. If the database is unreachable the server answers **503**
   `{"detail": "database unavailable: …"}` within its own bounds — 10 s to connect
   (`DB_CONNECT_TIMEOUT_S`) and 30 s per statement (`DB_STATEMENT_TIMEOUT_MS`) — it never
   hangs; the same 503 comes from `GET /board` and `/board/config`. Starts for different
   drafts don't queue behind each other; a second `start` for the *same* draft waits for the
   first and returns its runner.
2. **Poll** `GET /draft/{draft_id}/state?limit=40` every ~2 s. **Redraw only when
   `recompute.seq` changes** — the sequence number increments once per recompute, so an
   unchanged `seq` means nothing new. (The built-in fallback page does exactly this.)
3. **Render from the payload** (`DraftStateOut`, fully typed in the reference):
   - `clock` drives the header: `my_turn`, `picks_until_my_turn` (0 = on the clock),
     `on_the_clock` (slot number), `round`, `current_pick`, `complete`.
   - `my_roster` drives the needs view: `open_starters` (position → open seats), `open_flex`,
     `open_bench`, `picks` with their `seat`.
   - `rows` is the decision table, best pick first by `pick_score`. `rank` is the *overall*
     order — it does not renumber when you filter by `position`.
   - `recompute.error` non-null (or `stale: true`) means the last recompute failed and `rows`
     are the previous good ones — show a warning, keep rendering.
4. **404 on `/state`** means the runner isn't up (the `detail` says so) — offer a start button
   that does step 1.
5. The runner stops itself when the draft completes (`clock.complete`, `poller.status`
   `"complete"`); `POST /draft/{draft_id}/stop` stops it manually (404 if not running).
6. **A wrong draft id is not retried forever.** `start` itself succeeds (it doesn't call
   Sleeper), but if Sleeper answers 404 for `/draft/{id}` or its picks the runner retries once
   and stops: `GET /draft` shows `running: false`, and `/state` carries the reason in
   `poller.runner_error` (also `poller.summary.fatal`). Transient errors (timeouts, 5xx) keep
   the usual capped backoff and `poller.failures_in_a_row` — the runner stays up. Stopping the
   server (`Ctrl-C` on `lazy serve`) stops every runner within a few seconds.

`position` and `limit` filtering can be done server-side (query params) or client-side —
the fallback page filters client-side so position tabs don't cost a request.

## Workflow 2 — tuning the dials

All thresholds live in one server-side config row (`GET`/`PUT /board/config` — shape below).
Changing it does **not** affect a running draft until you push it:

- `POST /draft/{draft_id}/config` — applies the **draft-time** dials (survival, runs,
  need bonus, `late_rounds`) to the running engine: instant, one recompute.
  Response: `{draft_id, restarted: false, running, recompute_seq, error}`.
- `POST /draft/{draft_id}/config?restart=true` — stops and restarts the runner so the
  **board-time** dials (tiers, cliff, flags, `stream_depth`) take effect: board rebuild,
  a few seconds; state is restored from the DB.
  Response: `{draft_id, restarted: true, running, recompute_seq}`.

`GET /board/config.html?draft_id=…` is the no-code version of this flow (form → PUT → apply).
Outside a draft, `POST /board/regen` rebuilds and persists the pre-draft board under the
current config → `{"board": <board meta>, "rows": <count>}`.

### The dials (`GET`/`PUT /board/config`)

Response is a flat object: every dial below plus `updated_at`. `PUT` accepts any subset
(omitted/null = leave alone); numeric dials must be positive.

| Dial | Default | Applies at | Meaning |
|---|---|---|---|
| `min_gap` | 4.0 | board build (restart) | Minimum VORP gap to ever break a tier |
| `gap_multiplier` | 2.0 | board build (restart) | Tier break at gap ≥ multiplier × median gap |
| `cliff_gap` | 15 | board build (restart) | Absolute `gap_to_next` (season pts) that marks a CLIFF |
| `adp_min_delta` | 12 | board build (restart) | Min ADP-vs-rank delta to flag value/reach |
| `adp_pct` | 0.25 | board build (restart) | …or this fraction of ADP, whichever is larger |
| `disagree_min_pts` | 20 | board build (restart) | Min provider spread (pts) to flag disagreement |
| `disagree_pct` | 0.15 | board build (restart) | …or this fraction of points, whichever is larger |
| `debias_disagreement` | true | board build (restart) | Rescale providers by position-median ratio first |
| `stream_depth` | 6 | board build (restart) | K/DEF replacement level (K6/DEF6, waiver-aware) |
| `survival_sigma_min` | 4 | draft engine (instant) | Floor of the ADP survival-curve sigma |
| `survival_sigma_pct` | 0.12 | draft engine (instant) | Sigma as a fraction of ADP |
| `demand_shift` | 0.5 | draft engine (instant) | How much opponents' positional need stretches the window |
| `need_bonus` | 8 | draft engine (instant) | Points added to `pick_score` per unit of my positional need |
| `run_window` | 8 | draft engine (instant) | Look-back (picks) for run detection |
| `run_threshold` | 4 | draft engine (instant) | Position count in the window that flags a run |
| `run_streak` | 3 | draft engine (instant) | …or consecutive picks at the position |
| `late_rounds` | 3 | draft engine (instant) | K/DEF get need bonus only in the last N rounds (0 = always) |

## Untyped response shapes

The reference marks these as "object" because the app returns plain dicts. Their actual shapes:

### `GET /board` → `{"board": {...}, "rows": [...]}`

**`board`** (also the `"board"` value of `POST /board/regen`):

| Field | Type | Notes |
|---|---|---|
| `id` | integer | Board row id |
| `season` | integer |  |
| `provider` | string | `sleeper` \| `espn` \| `ensemble` |
| `baseline` | string | `live` \| `historical` |
| `generated_at` | string (UTC) |  |
| `row_count` | integer | Rows on the full board |
| `config` | object | Snapshot of the dial values the board was built under |

**`rows[]`** — the persisted pre-draft board row. Shares most fields with the draft-state
`DraftRowOut` (see the reference) but is a different set: it has **no**
`survival`/`run`/`run_count`/`pick_score` (those are live draft signals) and **adds**:

| Field | Type | Notes |
|---|---|---|
| `baseline` | number | Replacement-level points used for this position |
| `spread` | number \| null | Point spread between ensemble members |
| `components` | object \| null | Per-provider points, e.g. `{"sleeper": 210.5, "espn": 224.1}` |

### `GET /ensemble/weights` (also returned by the PUT/DELETE ensemble endpoints)

```
{
  "horizon": "season",                      // or "weekly" (?horizon=)
  "config": { "use_overrides": bool, "weights_version": int|null,   // null = latest
              "latest_version": int|null, "updated_at": str|null },
  "in_force": { "<POS>": { "weights": {"sleeper": 0.52, "espn": 0.48},
                            "source": str,          // fitted vs override
                            "version": int|null } },
  "fitted":    { "<POS>": {"sleeper": ..., "espn": ...} },   // this horizon's fitted rows
  "overrides": { "<POS>": {...} }
}
```

`DELETE /ensemble/overrides` prepends `"removed": <count>` to the same payload.

### `GET /snapshots` → array of

`{id, source, kind, season, week, pulled_at, record_count, valid, byte_size}` — newest first.

### Draft management

- `GET /draft` → `[{draft_id, running, season}]` — drafts known to this API **process**
  (in-memory; restarts forget stopped drafts).
- `POST /draft/{id}/stop` → `{draft_id, running}`.
- `POST /draft/{id}/config` → see Workflow 2.

## Field semantics (glossary)

- **`vorp`** — season points over the replacement-level `baseline` for the position.
- **`tier`** — per-position tier, 1 = best; breaks at large VORP gaps (see dials).
- **`cliff`** — true when `gap_to_next` ≥ `cliff_gap`: the last player before a big drop.
- **`adp`** — Sleeper PPR ADP. **`adp_delta`** = ADP − overall board rank; **`adp_flag`** is
  `"value"` (market takes him later than the board ranks him), `"reach"` (earlier), or null.
  Known bias: K/DEF skew `value` because the market drafts them far below their VORP rank.
- **`disagree`** — true when the providers' (debiased) projections split materially.
- **`survival`** — probability (0–1) the player is still available at *my next* pick.
  `null` when the player has neither ADP nor a search-rank to infer one from.
- **`run`** / **`run_count`** — a positional run is live in the recent pick window / how many
  of the last `run_window` picks were this position.
- **`pick_score`** — the recommendation order: `vorp − option_value + need_bonus × my need`.
  Option value discounts players likely to survive to your next pick, so a sure-to-survive
  player ranks below a now-or-never one of equal VORP.
- **`injury_status`** — Sleeper's status string (e.g. `Questionable`, `Out`); fresh as of the
  last `lazy pull players --load`.
- **`seat`** (roster picks) — the position code the pick fills (`QB`, `RB`, …), `"FLEX"`, or
  `"BN"` (bench). Seats fill greedily in pick order: dedicated → eligible flex → bench.
- **`needs`** (roster) — per-position urgency score: open starter 1.0 + flex share 0.5 +
  bench 0.25 × bench mix. Higher = draft this position sooner.
- **`poller.status`** — Sleeper's draft status: `pre_draft` → `drafting` → `complete`.
- **`recompute.stale`** — the advice shown is from before the latest pick (recompute failed);
  `recompute.error` carries the message.

## Errors

- **404** — draft runner not started (`/draft/{id}/state`, `/stop`, `/config`; the `detail`
  names the start endpoint), or no board persisted yet (`/board`, `/board.html` — run
  `POST /board/regen` or `lazy board regen`).
- **422** — validation: bad `horizon`/`provider`/`position` values, non-positive dials,
  pinning a fitted `weights_version` that doesn't exist.
- There is no 401/403 — the API is unauthenticated by design; don't expose it publicly.
